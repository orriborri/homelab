# Domain docs

This repository uses a single-context layout.

## Before exploring

Read root `GLOSSARY.md` if present, and ADRs in `docs/adr/` relevant to
the area being changed.

If the glossary or relevant ADRs are absent, continue silently.
Create glossary entries when terms are resolved, and ADRs when
architecture decisions are made.

## Vocabulary

Use the glossary's terms in issues, proposals, hypotheses, and tests.
If a needed concept is missing, reconsider the wording or note the gap
for domain-modeling.

## Decisions

Follow `docs/adr/README.md` when recording an architecture decision.
If a proposal conflicts with an existing ADR, identify the ADR and
explain why its decision should be reconsidered.
